# Design Spec: CI Drift Gate for Generated Documentation

- **Issue:** [#476](https://github.com/zhuxixi/jfox/issues/476)
- **Parent issue:** [#456](https://github.com/zhuxixi/jfox/issues/456)
- **Repository:** `zhuxixi/jfox`
- **Status:** Approved for implementation
- **Phase:** 3 — CI documentation drift gate

## 1. Problem

`docs/cli-reference.md` is generated by `scripts/generate_docs.py` (Phase 2A, #472/#474), but nothing in CI verifies that the committed copy is fresh. A contributor can change CLI commands or `docs/cli-descriptions.yaml`, forget to regenerate, and merge stale documentation — the exact drift #456 exists to prevent, merely relocated from hand-written tables to a generated artifact.

Two gaps make the problem worse today:

- The `lint` job has no step that regenerates and compares.
- The workflow path filters do not include `scripts/**` or `docs/cli-descriptions.yaml` (YAML is not matched by `**/*.md`), so a PR that only edits the description catalog can bypass CI entirely.

## 2. Desired outcome

A CI gate inside the existing `lint` job that regenerates the documentation and fails the PR whenever regeneration changes tracked files, with an actionable failure message. The gate must be impossible to bypass through the path filters, must keep the existing lint steps green, and must remain deterministic (verify-only, never writes commits).

Success criteria:

1. A PR that changes CLI commands or `docs/cli-descriptions.yaml` without regenerating `docs/cli-reference.md` fails CI with a message naming the regeneration command and the changed files.
2. A PR that touches `scripts/generate_docs.py`, `docs/cli-descriptions.yaml`, or CLI code under `jfox/` triggers the gate via path filters.
3. A docs-only regeneration PR still runs the gate.
4. `ruff`, `black`, and `markdownlint` continue to run and stay green in the same job.
5. README documents the local regeneration workflow.

## 3. Scope

### In scope

- One new step in the `lint` job of `.github/workflows/integration-test.yml`: run `uv run python scripts/generate_docs.py`, then fail on `git diff --exit-code` with actionable output.
- Path-filter additions to both the `push` and `pull_request` triggers: `scripts/**` and `docs/cli-descriptions.yaml`.
- A short maintenance subsection under the existing README `### Run checks` area explaining regeneration.
- Verification evidence: local shell simulation plus red/green self-proof commits inside the PR.

### Out of scope

- Plugin inventory checks and `NoteType`/`GemLevel` coverage checks (Phase 2B; planned as a second batch in the same gate afterwards).
- Internal/external Markdown link checking (separate follow-up; external checks belong on a schedule).
- Automated draft `docs-sync` PR (Phase 4).
- AI-assisted documentation review (Phase 5).
- The four low-severity advisories from PR #474 CR and the AGENTS.md/CLAUDE.md documentation-policy sync PR.
- Any change to the generator behavior or its tests; the gate consumes the generator as-is.

## 4. Gate design

### 4.1 Placement

Extend the existing `lint` job (option A from the design discussion). Rationale: the job already runs `uv sync --extra dev` (which installs everything the generator needs — `click`, `yaml`, and the `jfox` package itself), the branch-protection `quality-gate` check already depends on `lint`, and no new job means no duplicated environment setup and no `needs` changes. Rejected alternatives: a separate `docs-drift` job (duplicate checkout/setup, `quality-gate` rework) and attaching to `test-fast` (runs twice on two OSes, has skip conditions, mixes concerns).

### 4.2 Step behavior

Appended after the existing `markdownlint` step:

```yaml
    - name: Check generated docs are up to date
      run: |
        uv run python scripts/generate_docs.py
        if ! git diff --exit-code; then
          echo "::error::Generated docs are stale. Regenerate locally with:"
          echo "::error::  uv run python scripts/generate_docs.py"
          echo "--- Changed files ---"
          git diff --name-only
          exit 1
        fi
```

Design decisions:

- `git diff --exit-code` runs against the whole working tree, deliberately without path limits, so a future generator that writes additional files is automatically covered.
- Failure output uses `::error::` workflow annotations (visible inline on the PR) plus the changed-file list, so a contributor can fix drift locally with one command.
- The generator's own validations (YAML coverage, duplicate keys, schema shape) run for free inside this step and fail the gate with their existing actionable messages.
- The generator writes only `docs/cli-reference.md` today; its temp directories live in the system temp area and never touch the working tree, so no `.gitignore` change is needed.

### 4.3 Ordering

The drift gate runs after `markdownlint` and is the final step of the job. Existing steps stay untouched; the diff of this PR is minimal and the new step is the only behavioral addition.

## 5. Path filters

Add to both `push` and `pull_request` path lists:

```yaml
      - 'scripts/**'
      - 'docs/cli-descriptions.yaml'
```

Coverage reasoning after the change:

| Changed path | Triggered by | Notes |
|---|---|---|
| `scripts/generate_docs.py` | `scripts/**` | previously only indirect via tests |
| `docs/cli-descriptions.yaml` | explicit entry | YAML not matched by `**/*.md` — the real bypass hole |
| `docs/cli-reference.md` | `**/*.md` | already covered |
| `jfox/**` (CLI changes) | `jfox/**` | already covered |
| workflow file itself | self entry | already covered |

`packages/**` is deliberately deferred to Phase 2B (plugin inventory checks), which will extend the same filters.

## 6. README maintenance documentation

Extend the existing `### Run checks` section with one short paragraph (no new heading) stating:

- `docs/cli-reference.md` is generated from the live Typer command tree plus `docs/cli-descriptions.yaml`;
- after changing CLI commands or descriptions, run `uv run python scripts/generate_docs.py` and commit the result;
- CI fails when the committed reference is stale.

The README keeps its curated status; this is a maintainer instruction, not a generated-content section.

## 7. Acceptance matrix

All acceptance items are suitable for automation except U1, which is an optional manual smoke check of the `workflow_dispatch` path.

| ID | Feature point | Acceptance method | Verification | Pass criteria |
|---|---|---|---|---|
| A1 | Stale reference fails CI with actionable output | Automated (`automated E2E`) | PR commit sequence: (1) deliberately stale `docs/cli-reference.md` → CI red; evidence captured in PR | `lint` job fails; annotation contains the regeneration command and the changed-file list (`docs/cli-reference.md`) |
| A2 | Regeneration restores green | Automated (`automated E2E`) | Same PR: (2) local `uv run python scripts/generate_docs.py` + commit → CI green | `lint` and `quality-gate` pass; committed file is byte-identical to fresh generation |
| A3 | Path filters trigger the gate | Automated (`automated E2E`) | PR contains one commit that only adds a YAML comment to `docs/cli-descriptions.yaml` (no semantic change, generator output unchanged) | That commit triggers a workflow run in which the gate step executes and stays green — proving the new YAML filter entry works |
| A4 | Existing lint steps remain green | Automated (`build`) | Same PR CI | `ruff`, `black`, `markdownlint` steps pass; `quality-gate` green |
| A5 | Gate logic works locally | Automated (`automated E2E`, local) | `uv run python scripts/generate_docs.py && git diff --exit-code` in a clean checkout | Exit 0 with no diff |
| A6 | README documents regeneration | Automated (`static`) | `grep -n "generate_docs.py" README.md` | The regeneration command appears in README with a stale-fails-CI note |
| U1 | `workflow_dispatch` still works | User-tested (`manual`) | Trigger Fast dispatch on the PR branch | Dispatch runs; `lint` and `test-fast` behave as before |

## 8. Testability decomposition

This issue contains **no new Python code**. The gate's judgment logic is entirely composed of existing, separately tested tools:

| Boundary | Production unit | Verification strategy | New tests needed |
|---|---|---|---|
| Regeneration | `scripts/generate_docs.py` | Already covered by 28 Phase 2A tests (determinism, coverage, validation, config safety) | None |
| Drift judgment | `git diff --exit-code` | Proven tool; exercised by A1/A2 red/green self-proof and A5 local simulation | None |
| Failure rendering | shell `if ! … ; then … ; fi` in workflow YAML | A1 proves the red path, A2 proves the green path | None |
| Filter triggering | GitHub Actions `paths` engine | A3: the PR's own files prove triggering | None |
| README instruction presence | README text | A6 static grep | None |

Because the lowest-cost verification level that proves each behavior is `automated E2E` through CI itself (plus one local simulation and one static grep), no pytest additions are justified; adding unit tests for a shell `if` statement or GitHub's filter engine would test someone else's code. This is a deliberate, documented choice, not a gap.

## 9. Failure modes

| Failure | Gate behavior | Remediation visible to contributor |
|---|---|---|
| Committed reference stale | `git diff --exit-code` exits 1 | `::error::` annotation + changed-file list |
| `docs/cli-descriptions.yaml` missing a command entry | Generator raises `ValueError` with missing paths | Existing actionable message; gate red |
| Duplicate YAML key | Generator raises `ValueError` | Existing actionable message; gate red |
| Dependency/import failure in CI | Step exits non-zero | Standard step log; fail closed is correct |
| Windows contributor regenerates locally | Generator forces UTF-8/Unix newlines | Byte-identical to CI output (covered by Phase 2A Windows tests) |
| Generator later writes a second file | `git diff --exit-code` has no path filter | Automatically caught |

## 10. Compatibility and maintenance

- Single platform (Ubuntu), matching the existing `lint` job; generator determinism across OSes is already proven by Phase 2A's Windows CI.
- No new dependencies, no new workflow file, no `needs` or branch-protection changes.
- The gate verifies only; it never commits, pushes, or opens PRs.
- Future Phase 2B checks extend the same `lint` job and the same path-filter block; this phase deliberately leaves `packages/**` untouched.
