# 团队分享：让知识连成网——用 JFox 搭一个自己的知识库

> 约 8 分钟。每段开头一句是「段首概要」，照着念就行；破折号后的都是展开。

---

## 开场：一句话说明白今天要讲什么

大家好，今天分享的主题一句话就能说完：**我们用一个叫 JFox 的开源命令行工具，把散落各处的知识存成普通 Markdown 文件，再用链接、搜索和知识图谱把它们连成一张网。** 下面我分三块讲：它解决什么问题、日常怎么用、以及为什么它特别适合我们团队。

## 第一块：它解决什么问题——知识记了，但再也找不到

我们都有过这种经历：看过的好文章、调通的坑、开会的结论，当时记下来了，三个月后要么找不到，要么找到了也不知道跟别的东西有什么关系。这就是知识管理的经典难题：**记笔记不难，难的是让笔记在你需要的那一刻出现，并且带着它周围的上下文一起出现。**

JFox 的解法是一套有六十多年历史的方法，叫 Zettelkasten，中文叫「卡片盒笔记法」。它的核心思想很简单：不写大而全的文章，而是写一张张小的、原子化的卡片，每张卡片只讲一个观点，然后用链接把卡片串起来。德国社会学家卢曼用这套方法写出了七十多本书，这是他几十年积累的卡片网络的自然产物。

对我们做技术的人来说，这套方法最实在的一点是：**你的笔记永远是普通 Markdown 文件**。它不把你锁进某个专用数据库，你可以用任何编辑器打开、改、备份、迁移。工具坏了，知识还在。

## 第二块：日常怎么用——五步上手，两条工作流

JFox 本身是一个本地命令行的 Python 工具，装好之后，最快的一条路径只有五步：初始化、建笔记、加链接、搜一下。我现场过一遍：

```bash
jfox init

jfox add "原子笔记连起来才有用。" --title "Connected Notes" --type permanent

jfox add "关于起点原则，见 [[Connected Notes]]。" --title "A Linked Note" --type permanent

jfox search "connected notes"
```

第一条命令建知识库，中间两条建了两张卡片，注意第二条里的 `[[Connected Notes]]` 这种双方括号写法——这就是卡片盒里的双向链接：你写一个链接，工具自动在对方卡片上补一条反向链接，以后从哪一头都能顺藤摸瓜。最后一条是搜索，它叫「混合搜索」，意思是一次搜索同时走两条路：一条是关键词精确匹配，另一条是语义匹配，通过词向量找到「用词不同但意思相近」的笔记。你知道确切词就靠前者，只记得大意就靠后者。

日常工作主要就是两条工作流。**第一条是「记卡片、连卡片」**：笔记分几种类型——闪念笔记随手记，文献笔记记读书所得，永久笔记沉淀成熟的想法。想建立联系就写一个双方括号链接，而不是把上下文复制一遍。**第二条是「找和逛」**：`jfox search` 负责找，`jfox graph` 负责逛——它能把你的知识库画成一张图谱，你能看到一个主题连了多少张卡、哪些卡是没人引用的孤儿、从一个点出发两跳之内还有什么。主题特别密集的时候，还可以用 `jfox moc` 建一张地图卡（MOC，Map of Content），给这个主题一个人工整理的入口。

## 第三块：为什么适合我们——本地优先，而且能跟 AI 搭档

JFox 有几个设计取舍，我觉得是专门为我们这种环境考虑的。**第一是本地优先**：笔记、索引、搜索全在你自己机器上跑，数据不出门。只有两个可选项会碰网络：首次下载嵌入模型（之后就走本地缓存），以及一个可关的自动总结功能，它会调用 Claude CLI 把聊完的会话总结成笔记。开不开完全由你控制。**第二是它给 AI 搭档留了位置**：它本身带一条「宝石流水线」——AI 会话产生的碎片会被合成为「候选笔记」，标记为「破损级」，明确要求人来审阅，审过才晋升为正式知识。这条线的意思很清楚：AI 负责粗加工，人负责把质量关。工具对 Claude Code、Kimi Code 和我们用的 pi 都有现成的集成包。

## 收尾：一句话带走

总结成一句话：**JFox 不替你记知识，它替你管「连接」——记在哪、怎么找到、和谁相关——而连接，恰恰是单条笔记变成知识网络的关键。** 我的分享就到这里，安装命令和文档都在项目的 README 里，有问题随时找我。
